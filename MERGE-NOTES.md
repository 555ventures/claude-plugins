# MERGE-NOTES — spec plugin (FE dashboard × BE backend)

Audit trail for merging the two spec pipelines into the `spec` plugin. For every shared file
pair, each diff hunk is classified **drift** (one side simply better → adopted for both) or
**genuine** (real FE/BE difference → parameterized into host config / the init-generated
grounding layer, never an if/else in plugin files).

Sources (read-only): `~/Projects/tradoyo/dashboard` (FE), `~/Projects/tradoyo/backend` (BE).
Host-config surface decided: `.claude/spec.config.json` (machine knobs) +
`.claude/rules/spec-pipeline.md` (prose, six sections: Risk Tiers / Planning / Build /
Worker Rules / Test Rules / Review Checks), both generated by `/spec:init`.

## Open questions (deferred, not guessed)

1. **Legacy `/spec.X` spellings in the gate hook** — the plugin hook only matches `/spec:X`.
   If the source repos adopt the plugin while keeping muscle memory for `/spec.plan`, those
   invocations bypass the gate (they'd also miss the commands). Deliberately not double-matched;
   revisit at migration time.
2. **`agentMap.default`** — I introduced a required `default` key (sources hardcoded
   `general-purpose`). Falls back to `general-purpose` in the workflow if absent, so existing
   behavior is preserved; init writes it explicitly.
3. **design.md stage gates** — FE pins `bun typecheck` (Phase 1) and `bun typecheck && bun
   lint` (Phase 2). The plugin says "host typecheck / typecheck + lint" loosely; if a host's
   gateCommand isn't `&&`-separable, init should pin exact stage gates in pipeline rules
   § Build. Not modeled as config keys yet — would add two knobs for one consumer.
4. **BE `spec_drift.py --strict` / `--domain` modes** — only the `--spec` form is wired into
   review. The standalone `/spec.drift` command's all-domains sweep has no plugin equivalent;
   BE can keep invoking the script directly.
5. **`claude plugin validate --strict` vs no-version policy** — strict mode treats the
   missing `version` field as a warning-as-error. The no-version decision (git-SHA
   versioning) was explicit, so it wins: validation passes non-strict with exactly that one
   warning and zero others. If a clean strict run is ever required, the only lever is adding
   a version field.
6. **`spec-paths` and symlinked installs** — resolves via `dirname $0` without symlink
   chasing; fine for normal plugin installs, could mislocate if a user symlinks the binary
   elsewhere. Accepted.
