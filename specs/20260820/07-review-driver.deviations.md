# Deviations — specs/20260820/07-review-driver.md

- plugin.json bumped to 7.14.0, not the spec's literal 7.13.0 target: that version was already taken at HEAD (known [host] gotcha — concurrent sessions race the same semver; the spec's number is a target, not a pin).
- Ledger (`.claude/spec-runs.jsonl`) and `--retain` evidence are written under `repoRoot` (wherever the driver's CWD actually is — the build worktree during an isolated review), not under the main root, and are promoted (deduped by line/filename) into the main root's `.claude/spec-runs*` only once a merge has actually landed, with the worktree-local copies then deleted alongside the sidecar right before `merge-back.sh cleanup` runs. Writing them straight to the main root at CLOSE time (a literal reading of D10's "durable home") dirtied the main root's working tree before `merge` even ran, tripping `assert_clean_root`/breaking `ff-only`'s ancestor requirement (executed repro during build, AC-20260820-07-12); leaving them in the worktree unpromoted then made `git worktree remove` (no `--force` in merge-back.sh) refuse cleanup on the untracked files. Sole self-consistent ordering found; recorded since it reads D10 more operationally than literally.
- STOPPED is sticky/idempotent, not auto-retried on a bare re-invocation: a second no-mark call while the latest manifest is red-blocking re-prints STOPPED rather than re-running legs. A literal "a later invocation restarts at LEGS with a fresh manifest" (no dedicated unstick mark exists in D3's closed set) breaks even the test helper's own `stateOf()` pattern (a `--state`-only call right after the first STOPPED-producing call would append a second GATE_RED ledger line, executed repro during build, AC-20260820-07-2) and contradicts the general re-entrant/idempotent contract shared with DONE/ESCALATE. Retry now requires deleting the sidecar (or just the red iteration's manifest) after fixing the underlying issue; the STOPPED step's own printed remedy says so.
- FIX vs ESCALATE is not purely re-derived from manifest-<n>.jsonl count: a refused 3rd `fix-applied` and a not-yet-attempted 3rd attempt are identical on disk (same manifest count, same pendingFix=true), so a persisted `marks.escalated` flag — set only inside `handleFixApplied`'s own cap refusal, untouched by hand-editing `iteration`/`fixIterations` — distinguishes them. The cap arithmetic itself still derives solely from manifest files present on disk (AC-20260820-07-8's manifest-provable-cap test), per D2's Fragile Spots note.
- D2's "frozen-base check + detached-worktree add/remove" is implemented narrowly: base derivation is `build_base` → `diff_base` → a `git merge-base HEAD main|master` fallback, with no separate detached-worktree mechanism for a moved/stale base. No AC exercises a base-drift scenario and the spec names no concrete trigger condition for when a detached worktree would be needed; flagging as a scope simplification rather than guessing at an untested mechanism.
- A `done` spec with no `.review` sidecar present is read as the terminal DONE state (re-prints the next pointer, never auto-restarts), rather than literally "starts a fresh run" per the spec's Behavior prose. No AC exercises re-reviewing an already-done spec either way; DONE's terminal framing (alongside STOPPED/ESCALATE, all re-entrant/idempotent by design) was preferred over silently kicking off a new review cycle on what could be an incidental status check.
