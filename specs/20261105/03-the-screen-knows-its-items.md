# The screen knows its items

## Intent
- You asked: give `/spec:status` v7's screen exactly — the queue items carry the type and the `after` gate v7's did, migration fills them on niko-hub from the v7 backup, and the screen is a port of v7's `spec-status.js` through an adapter, byte-for-byte on the restored niko-hub v7 copy, with no additions and no ledger lines.
- I will build:
  - Queue items gain `type` (prompt items: `plan|prototype|fix|decide`) and `after` (`{brief}` or `{spec}`); `queue add` takes `--type` and `--after`; the one paste line (`/spec:plan <payload>`, `📌 decide: <payload>`) feeds `queue next` and the screen; an item whose `after` target is not done is not ready: `queue next` skips it, `list` marks it, fanout's PLAN waits it, the screen blocks it with `⏳ after brief 03`.
  - Brief doneness is v7's: a brief with specs is done when every live spec is done; a brief item is reconciled done with its brief, as spec items are today.
  - `lib/roadmap.js` holds the spec walk, the brief records and v7's strict `Depends on:` parser (an item is a dependency only when it is an exact brief id; `02-B (02a-2; parts of 02a-3a)` is brief 02, never `3a`), used by queue, fanout and status.
  - `status.js` renders v7's dashboard ported from `spec-status.js` — the entries, blockers, `⏳` branches, `⚠️` decide lines with their cap, `🕓`/`⛔` sections, `✨` wordings and footer — fed by an adapter over v8's items; the `📈` lines and the "done since last release" clause are absent; the `📥` block is gone. The lane block keeps spec 20261105/01's fan-out truth.
  - `migrate.js` carries `lane`→`type` and `after` from a v1 queue, and on a host already at v2 fills them from the newest git-dir `spec-v7-backup`, printing each fill; idempotent.
  - A test runs v7's own `spec-status.js` (from the `spec-v7-final` tag) and v8's on one fixture host and asserts the renders are byte-identical once v7's ledger-fed lines are dropped; golden files, queue, migrate and fanout tests; the interface contract and architecture notes reconciled.
- I will not touch:
  - `run.js` and the engine loop: a parked run's `/spec:fix <spec> — …` item is a prompt whose payload already names its command and spec; no `origin` field, no ledger, no red-check or disposition change.
  - The lane admission rule (spec 20261105/01 D5: lanes are what `/spec:fanout` would start), the `⚡ … — /spec:fanout` header, the in-flight footer heads, the `⚠️ Pending questions` block, doctor-fed hygiene, the `NN` mode and the `@` strip — v8 has them, v7 had no equivalent, and they stay as shipped.
  - The queue's `done`, `move`, `show` verbs, duplicate refusal, `--top`; the plugin version (ADR-0039 D4: bumped at release).
- Architecture or behaviour change: yes — the queue model gains `type` and `after`, brief items complete with their brief, the roadmap's doneness rule changes, and the screen departs from ADR-0039 D6 (no ledger-derived status lines, ever), needs your yes

## Goal

`/spec:status` on niko-hub prints the screen JJ used under v7: `✅ 02b–02c done`, `q70   /spec:plan service_type CHECK …`, every `after`-gated item under `⛔ blocked:` with `⏳ after brief 03`, `🟢 next is ready · 13 more open` — and nothing v7 did not print, the ledger lines included. Migration fills the 18 field values niko-hub's items lost in the v7→v8 move; `queue add --after 03` gates a new item the same way; fanout never starts a gated spec.

## Decisions

| ID | Decision | Why |
|----|----------|-----|
| D1 | Same UI/UX as v7, no additions — JJ's ruling. The screen is v7's `spec-status.js` dashboard (tag `spec-v7-final`) ported, not redesigned: `deriveNext` (entries, blockers, the sort), the `⚠️` decide lines, `🕓`/`⛔`, the `✨` wordings, `🚦 solo`'s condition, the footer clauses. The `📈 suite runs per spec` / `📈 test:production lines` lines and the `· N done since last release` / `· N done, never released` footer clause are absent: v8 has no ledger and the screen never shows ledger metrics. The `📥 N hardened specs are not queued` block and the `✨ queue empty` line are removed; unqueued hardened specs are entries, as in v7. | The earlier v8 rewrite drifted because it worked from a text capture; porting the code keeps the bytes. The ledger lines arrived in v7 two days before the tag and were never JJ's everyday screen. |
| D2 | Queue item shape: `{id, kind, payload, added, done?, type?, after?}`. `type` is on prompt items only, one of `plan|prototype|fix|decide` (v7's lanes). `after` is `{brief: "NN"}` or `{spec: "specs/…md"}` on any kind. No `origin`: nothing writes one. | The two fields are what v7's items carried on niko-hub and what the screen needs: the paste's command and the gate. |
| D3 | `queue add <payload> [--top] [--type <t>] [--after <NN\|spec path>]`. A prose payload's type defaults to `plan`; a payload starting `/spec:fix `, `/spec:plan ` or `/spec:prototype ` gets that type; `--type` overrides and is refused (exit 2) with a spec or brief payload or an unknown value. `--after` takes a brief id or roadmap path (stored `{brief: NN}`) or a spec path (`@` and `./` stripped, stored root-relative as `{spec}`); a target with no file is refused (exit 2) naming it. | One write path; the default makes every new prose item paste-ready, which is the point of the screen. |
| D4 | The one paste line, `pasteLine(root, item)`: a spec item `/spec:run`/`/spec:plan <path>` as today, a brief item `/spec:plan <brief path>`, a prompt item `<command> <payload>` for type plan/prototype/fix (`/spec:plan`, `/spec:prototype`, `/spec:fix`), `📌 decide: <payload>` for decide, and the payload verbatim when it has no type or already starts with its type's command. `queue next` prints it; the screen's `qNN` rows show it cut to the width. | v7's `promptAction`, so a migrated lane-less item (niko-hub q37) prints verbatim as it did. |
| D5 | Readiness: an item with `after` is ready when the brief is done (D6) or the spec is `done` or `superseded`; a target with no file or no brief is not ready, state `missing`. The blocker string is `after brief NN (<state>)` or `after <spec path> (<state>)` with v8's state words; the screen prints it through `shortBlocker` as `⏳ after brief 03` / `⏳ after 08-server-timeouts…`. `queue next` returns the first pending ready item (`queue empty` when none is ready prints `nothing ready — N waiting on after gates`); `list` appends `⏳ after brief 03` to an unready row. `fanout.js eligible()` treats an unready spec item as one more spec 20261105/02 D1 entry with why `after brief 03 (open)`. | The gate means "not before 03"; a fan-out that ignored it would make the screen lie. |
| D6 | Brief state (v7's rule): no live spec → `open`; every live spec `done` → `done`; else `implementing`; a `> Superseded by` banner → `superseded`. Live = not `superseded`. `reconcile` marks a brief item done when its brief is done, written on the next write, exactly as a spec item whose spec is done. Spec 20261105/01 D2's "and the brief's queue item ticked" is retired. | niko-hub's 02b and 02c are done briefs with pending items; v7 showed them done and never asked for a tick. |
| D7 | `lib/roadmap.js` owns `allSpecs(root)` (every `specs/**/*.md` with frontmatter; `.run/` skipped), `briefs(root, specs)` (one record per `docs/roadmap/NN-slug.md` minus `00-overview.md`, sorted number then letter) with `num, slug, file, title, phase, depends, state, done, total`, and `briefNo`. `Depends on:` is parsed as v7 did: the text before the first `## ` heading with HTML comments removed and whitespace collapsed, the value up to the next `·` or `Label:`, split on commas outside parentheses, each item kept only when it matches `^(brief )?\d{1,2}[A-Za-z]?(-[\w-]+)?( \(.*\))?$` and normalised to `NN`/`NNa`, duplicates collapsed; everything else is dropped. `queue.js`, `fanout.js` and `status.js` use it; `status.js`'s own `allSpecs`/`briefs` go. | Three scripts need one brief state; the loose `\d+[a-z]?` parser read `3a`/`3b` out of 02a's header on niko-hub. |
| D8 | Screen derivation, from v7 with the adapter: entries are every non-done spec in a known status (`draft` → `/spec:plan`, else `/spec:run`) plus every pending prompt item (`path: null`, the paste line as its text, `id`); blockers are unfinished `depends_on` specs, a draft's brief dependencies with no spec at implementing or done (`brief NN (<state>)`), and D5's `after` gate (a spec item's own, else its brief item's); the sort is blocked-last, queue position (a spec's own item, else its brief's, else last; prompts at their position), implementing < hardened < draft, brief order, path. When no entry is unblocked and an unplanned brief has every dependency met, `/spec:plan @<brief file>` is the top pick. The Next block prints unblocked prompt rows, then the lane block of spec 20261105/01 D4–D5 (run or fan-out in flight first), else the blocked top pick with its `⏳` branches, else `   ✨ nothing next — no specs or briefs found` / `   ✨ nothing actionable — all specs done; N unplanned brief(s) blocked on unmet dependencies` / `   ✨ nothing next — all specs done, no unplanned briefs`. `🚦 solo` prints when other unblocked or blocked entries exist. `--all` adds `🕓 after that:` (spec 20261105/01 D6 reasons) and `⛔ blocked:` listing blocked prompts and specs in entry order, each with its `⏳` branches, minus a top pick already printed blocked. | This is v7's block, with the lanes decided the v8 way. |
| D9 | Decide lines, from v7: `skipped-brief` — a brief that is implementing or done while a dependency brief is unplanned — prints `⚠️ Brief NN (<slug>) moved on, but its dependency MM (<slug>) was never planned.` then `   Plan it now?  /spec:plan @docs/roadmap/MM-<slug>.md`; `out-of-order` — an unplanned brief numbered below the highest brief that moved, not already named as a skipped dependency — prints `⚠️ Brief NN (<slug>) is unplanned while later brief MM has moved on.` then `   Still wanted?  /spec:plan @docs/roadmap/NN-<slug>.md`. They sit after the Next block (and after `🕓`/`⛔` under `--all`), capped at three in derivation order; `--all` lifts the cap; the footer gains `· N more to decide (--all)` for the overflow. | The only questions v7's screen asked; both are choices only the reader can make. |
| D10 | Footer: `⬜ nothing waits` with no entries; `🟠 next is blocked · waiting on <short blocker>` when the first entry is blocked; else `🟢 next is ready`; v8's in-flight and pending-question heads stay. Clauses in order: `N more open` (entries minus the top pick; `nothing else open` at zero on a 🟢 line), `N more to decide (--all)`, `N hygiene finding(s) (/spec:doctor)`. Nothing after that. | v7's footer minus the release clause. |
| D11 | `migrate.js`: `convertQueue` carries `lane` → `type` and `after` → `after` (`{brief}` normalised to `NN`/`NNa`, `{spec}` as written). A new op `queue-fields` applies when the queue is already v2 and the newest `<git-common-dir>/spec-v7-backup/*/spec-queue.json` holds an item of the same id with a `lane` or `after` the v2 item lacks: the plan lists `queue-fields <path> (N fills)` and one line per fill (`q70 type plan`, `q89 after brief 03`, `q108 after specs/…/08-….md`); `--apply` writes them; a second run plans nothing. | niko-hub was migrated before these fields existed; the backup is the only copy of them. |
| D12 | The oracle test: `git archive spec-v7-final spec/scripts` from this repo into a tmp dir, fail loudly when the tag is missing; a fixture host with briefs, specs in every state and a v1 queue holding lane-less, `plan`-lane, `after`-gated (brief and spec, met and unmet) prompt and spec items; v7's `spec-status.js --root <host>` and `--all` captured; `migrate.js --apply` on the host, then v8's `status.js`; equal byte-for-byte after removing from v7's output the two `📈` lines and the `· N done…` clause, and from v8's the fence lines. Golden files under `tests/fixtures/status/` are regenerated for the fixture of spec 20261105/01 and stay the pin for the v8-only states. | A text capture drifted once; the script itself is the golden. |
