# The v7 screen on v8

## Intent
- You asked: `/spec:status` (and the bash `spec-status`, the same script) must have exactly v7's behaviour and UI/UX, built cleanly on v8's architecture — not v7's code copied in. The only exception: the two `📈` lines and the "done since last release / never released" footer clause are absent.
- I will build:
  - `scripts/status.js` rewritten as v7's derivation ported onto v8's modules: v7's entries, blockers, queue overlay, pairwise lane admission with no cap, `⚡`/`🚦 solo`/`🔶`/`⏳`/`✨` lines, `⚠️` decide lines, `🕓`/`⛔`/`🧹` under `--all`, v7's footer, `NN` mode in v7's words, v7's flag refusals.
  - `lib/next.js`: v7's anomalies (v7's hygiene kinds minus `prototype-open`, remedies naming v8 commands), `deriveNext`, `laneAdmission`, the empty-state lines — one derivation for the screen and `--json`.
  - `lib/state.js parseFilePlan` reads every File Plan table with a `file` or `path` header and adds `filePaths` (cells split on `+`, commas and `{a,b}`, `(generated)` stripped); `filePlan` rows stay as run.js prints them.
  - The oracle: v7's `spec-status.js` from tag `spec-v7-final` (`git archive`) run beside v8's `status.js` on three fixture hosts, byte-identical bare and `--all` after the ledger lines are removed; regenerated goldens; manual read-only checks on `~/projects/niko-hub` and `~/projects/shop-bltr` recorded in the close commit.
  - `spec/commands/status.md` wraps the output in a fence and narrates as v7's command doc did; the bash `spec-status` prints the raw screen. `docs/v8/interface-contract.md` §1/§5 and `docs/v8/architecture.md` §9 reconciled.
- I will not touch:
  - The engine: `run.js`, `fanout.js`, `queue.js`, `migrate.js`, worktrees, sidecars, `doctor.js` (it stays the deep audit and is no longer called by the screen).
  - `lib/work.js` beyond what spec 04 built; the queue file; `~/projects/niko-hub` and `~/projects/shop-bltr` (read-only runs only).
  - v7's `--next`, `--lanes --json` and `--pretty` modes, the `↳ from` provenance line, `when` predicates, the `prototype-open` anomaly: not carried (ADR-0041).
  - The plugin version (ADR-0039 D4: bumped at release).
- Architecture or behaviour change: yes — the screen's derivation is v7's (lanes are pairwise-admitted with no cap, specs/20261105/01 D5 retired; hygiene comes from the derivation's own anomalies, not `doctor.check`; `--json` takes v7's shape), recorded in ADR-0041. JJ said yes on 2026-11-05 in the main session, covering this spec, spec 04 and their locks.

## Decisions

| ID | Decision | Why |
|----|----------|-----|
| D1 | The design is v7's `spec/scripts/spec-status.js` at tag `spec-v7-final`, read as the reference and ported function by function into v8's modules; no file is carried verbatim and no second parser is written (ADR-0041 §4). Where this spec is silent, v7's code decides and the oracle (D12) is the arbiter. The only output differences from v7: no `📈` lines and no `· N done since last release` / `· N done, never released` clause (ADR-0040), and the two anomaly remedies in D7 that name v8 commands. | Two rebuilds from a text capture drifted; the code is the screen, and the proof is the script itself. |
| D2 | Modules: `status.js` (argv, modes, render, ≤400 LOC, `build`/`main` exports kept), `lib/next.js` (≤250 LOC: anomalies, `deriveNext`, `laneAdmission`, `nothingNextLine`, `shortBlocker`), `lib/work.js` from spec 04 (`readSpecs`, `readBriefs`, `normBrief`, `briefOrd`), `lib/state.js` for the queue, config and `parseFilePlan`. `parseFilePlan` walks every table in the `File Plan` section (a table = a maximal run of `\|` lines; its first row binds columns when a cell matches `/^(file\|path)s?$/i`, else column 1 is the path), keeps `filePlan` rows `{path, action, summary}` as today for run.js, and adds `filePaths`: every path cell split on `\s*\+\s*` and `,\s*`, `{a,b}` braces expanded, a trailing `(…)` stripped, backticks removed, entries kept when they contain `/` or an extension (or are one bare token on a row whose Action opens with create/modify/delete/rename/move), deduplicated in first-seen order. | One File Plan parser for the screen's `🔶` overlap and the builder brief; shop-bltr's `a + b` and `{a,b}` cells must overlap as v7 saw them. |
| D3 | Inputs. Specs: `readSpecs(root)` (a spec with no `status:` skipped; `superseded` specs retired — no brief membership, no entry, no anomaly — and a `depends_on` naming one never blocks). Briefs: `readBriefs(root, specs)`. Queue overlay, read-only, as v7's `resolveQueueOverlay`: off when `git rev-parse --git-dir` ≠ `--git-common-dir` (a linked worktree), when git fails, or when the file is absent; an unparseable file or one without an `items` array turns the overlay off and adds one `queue-unparseable` anomaly. Items are v8's (`reconcile` applied in memory, nothing written). Virtual reconcile, computed only: duplicate `brief` items (by `normBrief`) and `spec` items (by path) collapse to their first occurrence; every item, done ones included, keeps its index as the queue position; every on-disk brief whose status is neither `done` nor `superseded` and has no item is appended last, in roadmap order. A brief item whose brief has no `docs/roadmap/NN-*.md` and is not done is a `queue-orphan` anomaly. | v7's overlay rules; item 16 of the audit (a ticked brief keeps its position) and item 22 (`3`/`05` are the same brief, no false orphan). |
| D4 | Entries (v7's `deriveNext`): one per live spec with status in `draft \| hardened \| implementing` — `draft` → `/spec:plan`, else `/spec:run`; a status outside `draft \| hardened \| implementing \| done` is an `unknown-status` anomaly and no entry. Blockers, in order: each `depends_on` whose live target (by path, basename, or `endsWith('/' + ref)`) is not done → `<target path> (<status>)`; for a `draft` with a known brief, each brief dependency with no member spec at `implementing` or `done` → `brief NN (<brief status>\|missing)`; a queue gate on the spec's own item, else on its brief's item → `after <target> (<state>)` where target is `brief NN` or the spec path and state is the brief status, the spec status, or `missing`. Prompt entries: every pending prompt item, `action` = spec 04's paste line, `path: null`, blockers from its own gate, `__queueId`. Rank: implementing 0, hardened 1, draft 2. Sort: unblocked first; queue position (a spec item's own, else its brief's, else Infinity; prompt entries their own); rank; `briefOrd`; path. The unplanned-brief pick: when no entry is unblocked (prompt entries count), the first brief by `briefOrd` with status `unplanned` whose every dependency brief has a member at `implementing`/`done` is unshifted as `/spec:plan @<brief file>` with `rank -1`. `top` = the first entry, or the first non-prompt unblocked entry when the first is a prompt; each unblocked non-prompt runner-up gets `parallel`/`parallelReason` against `top`: same brief → `shared brief NN`, a transitive `Depends on:` path either way → `brief A depends on B`, else parallel. | v7's derivation on v8's state; a spec in a lane worktree is `implementing` (spec 04 D6) and so ranks first, as niko-hub's 06 and 10 and shop-bltr's four lanes did. |
| D5 | Lanes (v7's `laneAdmission`, uncapped, ADR-0041 §5): over unblocked non-prompt entries, `lanes = [first]`, then each runner-up with `parallel === true` joins unless it has a serial reason against a lane already admitted after the first (then it is `laneClash`); `later` = the unblocked rest. Render under `🎯 Next`: pending unblocked prompt rows first (`qNN` padded to the longest id among prompt entries, two spaces, the paste text flattened and cut to `process.stdout.columns \|\| 100` with `…`); then, with two or more lanes, `⚡ N parallel lanes — first stays on main, each other lane gets a worktree (/git:enter-worktree):` and one `<action> @<path>` line per lane, then one `🔶` branch per overlapping pair in lane order — `   ├─ 🔶 <a.md> × <b.md>: merge-conflict risk: f1, f2 (+N more)` with the `<a> × <b>: ` pair prefix only when there are three or more lanes, `└─` on the last; with one lane, its line and `   └─ 🚦 solo` when `later` or any blocked entry exists; with no lane and no prompt row, the top entry with its `⏳` branches (`├─`/`└─`, blocker through `shortBlocker`: directories and `.md` dropped, trailing `(state)` dropped); with no entry at all `   ✨ <nothingNextLine>`. The top pick is never printed above `⚡`. `config.lanes` and fanout's admission are not consulted. | The header says what the block is: advice to a person opening worktrees. Every printed lane is startable now; fanout prints its own batch at PLAN. |
| D6 | `--all` adds, after the Next block: `🕓 after that:` listing `later` with one `   └─ ⛓️ <reason>` shared by consecutive equal reasons — the reason is `parallelReason` or the `laneClash` reason, only `shared brief NN` / `brief A depends on B`; then `⛔ blocked:` listing every blocked entry (prompt rows included) except a top pick already printed with its branches, each with its `⏳` branches; then the decide lines; then `🧹 Hygiene (N) — /spec:doctor` with `   [kind] detail` per hygiene anomaly, in derivation order. The default screen prints none of these sections. | v7's sections and order; the `🤷` reasons, the `📥` block, `✨ queue empty`, `⚠️ Pending questions` and the doctor-fed hygiene lines are gone. |
| D7 | Anomalies, v7's kinds and detail strings, derived in this order: `queue-unparseable`, `queue-orphan`, `unknown-status`, `orphan-stamp`, `unparsed-dependency`, `unknown-dependency` and `skipped-brief` (a brief not `unplanned`/`superseded` whose dependency is unplanned), `out-of-order` (an unplanned brief ordered before the highest brief that moved, skipping one already named as a skipped dependency), `skipped-spec` (a done spec whose live dependency is not done), `hand-tracked-status` (a status-like cell in `00-overview.md` rows starting `\| NN \|`). `skipped-brief` and `out-of-order` are decide anomalies with v7's `line`/`ask`/`paste` (`Brief 03 (slug) moved on, but its dependency 02 (slug) was never planned.` / `Plan it now?  /spec:plan @docs/roadmap/02-slug.md`; `Brief 01 (slug) is unplanned while later brief 04 has moved on.` / `Still wanted?  /spec:plan @docs/roadmap/01-slug.md`); every other kind is hygiene. Two remedies name v8 commands: `queue-orphan` ends `remove it with \`/spec:queue done NN\`, reorder it away with \`/spec:queue move NN <n>\`, or restore the brief file`; `queue-unparseable` ends `reseeded with \`/spec:queue next\`)`. `prototype-open` is not carried. | v7's hygiene is the derivation's own; doctor keeps the host checks (sidecars, worktrees, config). |
| D8 | Decide lines and footer. After the Next block (and the `--all` sections): a blank line, then `⚠️ <line>` and `   <ask>  <paste>` per decide anomaly, three by default, all under `--all`. Footer: the last line, `<glyph> <head>` plus clauses joined by ` · `: glyph/head `⬜ nothing waits` with no entry, `🟠 next is blocked · waiting on <shortBlocker(first blocker)>` when the first entry is blocked, else `🟢 next is ready`; clauses: `N more open` where N = entries minus one (the `🟢` line prints `nothing else open` at zero; `🟠` prints it only when N > 0), `K more to decide (--all)` when the default cap hid K, `H hygiene finding(s) (/spec:doctor)` when H > 0. No `📈` lines, no release clause. | v7's wording; `· N more to decide` and the anomaly-based hygiene count were missing from v8. |
| D9 | Roadmap block: printed only when briefs exist, as a blank line then `🗺️ Roadmap`; rows in `readBriefs` order; runs of consecutive briefs with the same status among `unplanned`/`done`/`superseded` collapse to `NN–MM` with the phase range (`P0–P1`, `—` when none) and `done (N briefs, M specs)` (M = member specs) or `<status> (N briefs)`; an `in-flight` brief never collapses and prints `NN name`, its phase or `—`, and the bar `'▓'.repeat(nDone === total ? 10 : min(9, floor(nDone/total*10))).padEnd(10, '░') + ' nDone/total'` over its members (drafts included, superseded excluded), or its status word when it has no member; glyphs `✅ 🔨 ⬜ ⛔`; label and phase columns padded by `String.length` (UTF-16). A superseded brief with done members is `⛔` with a full bar inside a collapsed range or alone. | v7's roadmap; niko-hub's `02b–02c` merge into one done range because a done brief needs no tick. |
