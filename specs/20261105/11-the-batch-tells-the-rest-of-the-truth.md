# The batch tells the rest of the truth

## Intent
- You asked: close spec 20261105/10's four review advisories — fanout stamps `held` only from the trunk state right after the mark's own step, so when the trunk gate goes red later in the same settle pass the other done lanes get no held line (D2 says every done lane gets one); fix lanes add no "touched outside the File Plan" bullets although D5 requires them, so decide what a fix lane's plan is (spec 09 made spec-less fixes a driver with `state.fix` as an object); A8 was false — the status full-host fixture got a `done` stamp on q16 instead of regenerated goldens, so the full-host golden never shows the decide line; and the sent-back WAIT body now ends with a lane list, so either update D3 or move the list.
- I will build:
  - `held` is stamped where the hold happens: a landing that turns the trunk red stamps every other `done` lane inside the same settle, a mark run while the trunk is already red stamps the lanes it leaves `done` and never the landed one, and MERGE_RED accepts `returned` so a lane that comes back while the trunk is red gets its held line instead of a refusal.
  - A spec-bound fix lane's plan is its spec's File Plan plus the regression test `fix.json` names; every other changed file becomes a `(fix: <symptom>) touched outside the File Plan: <path>` bullet under `## As built` and is listed in the reviewer brief; a spec-less fix has no spec, so no plan and no section, as today.
  - The status goldens gain `brief-queued.txt`: the full host with q16 left pending, showing the `brief-done-queued` decide line; the oracle host and the four existing goldens are untouched because v7's script never printed that line.
  - The sent-back WAIT body is recorded as the dispatch body followed by the lane list; fanout.md, the contract and the architecture notes say so, and the architecture note's stale landing sentence is rewritten to spec 10 D1's rule.
- I will not touch:
  - Spec 10's text and Decisions (this spec records what supersedes its D3 clause and its A8 arm); ADR-0041; `queue.js`, `lib/next.js` and the brief-closing rule (spec 10 D6).
  - `askedScope` for fix lanes: a fix never stops for scope (spec 09's one-stop rule); the outside-plan bullet is a record, not a stop. The spec-less fix (no spec, no `## As built`). MERGE's sent-back body and the `resent` mark.
  - The four existing status goldens, the v7 oracle hosts and their normalisation (ADR-0041 §6); the decide-line counts the spec 05 tests assert on the full host.
  - `block-worker-git.sh`; the plugin version (ADR-0039 D4).
- Architecture or behaviour change: no — fanout's output gains the held lines spec 10 D2 already promised and one accepted mark, run.js's `## As built` gains the bullets spec 10 D5 already promised, a test fixture gains a variant and a golden, and three docs are corrected; no ADR is added or overturned.
- Client sign-off: none

## Goal

Spec 10 promised that a mark says what it did to every lane, that the spec on trunk records every departure, and that the status goldens are the screen's own record. Four gaps were accepted as review advisories at its merge and lost with the worktree. After this spec every `done` lane that a red trunk holds back is named in the mark that held it, a fix lane records the files it touched outside its spec's plan, a golden shows the `brief-done-queued` decide line without breaking the v7 oracle, and the sent-back WAIT body's shape is what the doctrine says it is.

## Decisions

| ID | Decision | Why |

| D1 | `held` is stamped where the hold happens. `fanout.js` gains `holdDone(s)`: stamps `held` with detail `trunk gate is red` on every lane whose `status === 'done'` except `s.red.lane` — the lane whose landing turned the trunk red keeps its `landed` stamp until `gate-repaired` finalizes it. `gateAfter`'s red branch calls it right after setting `s.red`, inside the settle, so a landing that turns the trunk red stamps every other `done` lane under the same `s.seq` and the `after` hook prints `lane N landed as <sha>` and `lane M held — trunk gate is red` in the same mark. The `TOUCHING` wrapper calls the same helper instead of its own loop, so a mark run while the trunk is already red stamps the lanes it leaves `done` and never the landed one. `deriveRed` accepts `returned` beside `dismissed`: a lane that comes back MERGE_READY while the trunk is red is marked `returned --lane N` exactly as at WAIT, becomes `done`, prints its held line and lands in `gate-repaired`'s settle; a `--stopped` or question-bearing return becomes `stopped` and is relayed after the repair (WAIT hands on to RELAY). `applied` is unchanged: a lane already `done` or `stopped` is already-applied by the existing rule. The header comment names both stamping places. | Spec 10 D2 promised every `done` lane a held line and AC-20261105-10-2 a held line for a lane that returns while the trunk is red; on trunk the stamp ran before the settle and MERGE_RED refused `returned`, so the test faked WAIT with `s.red` and the real flow printed nothing. |

## Acceptance Criteria

- **AC-20261105-11-1**: WHEN three lanes are out on a host whose gate fails while a file `RED` exists, lane 3 is `done` and lane 2 returns MERGE_READY with a tree that adds `RED` THE SYSTEM SHALL, in lane 2's `returned` mark, print `lane 2 landed as <sha>` and `lane 3 held — trunk gate is red` under the checkpoint, leave the driver at MERGE_RED with lane 3 still `done` and trunk's head at that sha; AND the same mark with `--json` SHALL print neither line.
- **AC-20261105-11-2**: WHEN the driver is at MERGE_RED after lane 1 landed and lane 2 returns MERGE_READY THE SYSTEM SHALL accept `returned --lane 2`, set lane 2 `done`, print `lane 2 held — trunk gate is red` and no `lane 1` line, and leave trunk's head unchanged; AND WHEN `gate-repaired` is then marked on a repaired trunk THE SYSTEM SHALL print `lane 2 landed as <sha>` where `<sha>` is trunk's new head and report both lanes merged.
- **AC-20261105-11-3**: WHEN the driver is at MERGE_RED after lane 1 landed and `dismissed --lane 3` is marked THE SYSTEM SHALL print no `lane 1 held` line; AND WHEN lane 2 returns at MERGE_RED with `--stopped "<reason>"` THE SYSTEM SHALL set it `stopped` and, after `gate-repaired`, settle at RELAY naming lane 2.
- **AC-20261105-11-4**: WHEN a spec-bound fix lane (`run.js <spec> --fix x`) changes `src/extra.js` (outside the spec's File Plan) and `t.test.js`, `fix.json` holds `"test": "t.test.js :: guards c"` and `as-built.md` holds one line THE SYSTEM SHALL print at REVIEW `Files changed outside the File Plan: src/extra.js (a fix's plan is the spec's File Plan plus its regression test)` and, at COMMIT, append `- (fix: x) touched outside the File Plan: src/extra.js` and no bullet naming `t.test.js` under `## As built`, reaching MERGE_READY; AND WHEN the fix changes only File Plan files and `t.test.js` with no `as-built.md` and no advisory THE SYSTEM SHALL append no section.
- **AC-20261105-11-5**: WHEN a spec-less fix lane changes a file THE SYSTEM SHALL print `Files changed outside the File Plan: n/a (fix — it has no File Plan)` at REVIEW and commit no `## As built` anywhere; AND WHEN a spec-bound fix changes a file under the host's `askPaths` THE SYSTEM SHALL not stop with `scope`.
- **AC-20261105-11-6**: WHEN the status golden test runs THE SYSTEM SHALL find `tests/fixtures/status/brief-queued.txt` byte-equal to the bare render of `fullHost({ openBrief: true })`, containing `⚠️ Brief 01 (foundation) has every spec done but is still queued.` followed by `   Close it?  /spec:queue done 01` and the footer clause `· 3 more to decide (--all)`; AND `bare.txt`, `all.txt`, `brief-met.txt` and `brief-unmet.txt` SHALL be byte-identical to today's, AC-20261105-05-1's oracle SHALL still pass on every host, and `specs/20261105/11-the-batch-tells-the-rest-of-the-truth.run/evidence.md` SHALL hold v7's bare render of the open-brief host's v1 twin, containing no `still queued` line, beside v8's.
- **AC-20261105-11-7**: WHEN WAIT is printed with a sent-back lane THE SYSTEM SHALL print the dispatch body (its intro and the lane lines with Agent calls), then one blank line, then `Lanes (status · run step):` with one line per lane in batch order, and nothing after the list.
- **AC-20261105-11-8**: WHEN `spec/commands/fanout.md`, `docs/v8/interface-contract.md` and `docs/v8/architecture.md` are read THE SYSTEM SHALL find, in fanout.md, that the re-send dispatch is followed by the lane list and that `returned` is accepted at MERGE_RED; in the contract's fanout row `returned` at MERGE_RED and in its run row the spec-bound fix's plan (File Plan plus regression test); and in architecture.md no sentence saying a landing waits while a lane is `sent-back` or mid-rebase, plus `gateAfter` named beside `held`.
- **AC-20261105-11-9**: WHEN the suite runs after this spec THE SYSTEM SHALL pass the rewritten AC-20261105-10-9 test (the outside bullet present, the regression test exempt) carrying this spec's AC id beside the old one, and every other existing test unchanged.

## Assumptions

- A1: Behaviour change only, no ADR added or overturned: ADR-0041 §6 is honoured by leaving the oracle host as it is (D3), and ADR-0041 §2's sentence "The queue's reconcile ticks a brief item once its brief is done" was already overturned by spec 10 D6 with JJ's sign-off and is not touched here — if false: set `architecture: true`, re-lock with `--confirmed` after JJ's yes.
- A2: `fix.json`'s `test` names the regression test file before ` :: ` (spec 09 D2's format) — if false: nothing is exempt, the test file is listed as outside the plan, and the brief format is unchanged.
- A3: The decide block's order on the open-brief full host (`brief-done-queued` first, then `skipped-brief`, then the `out-of-order` lines) is `lib/next.js`'s queue-walk order and is stable — if false: the golden is whatever `UPDATE_GOLDENS=1` writes and AC-11-6 asserts its two lines by inclusion, not position.
- A4: The lane whose landing turned the trunk red is `s.red.lane` and is the only `done` lane carrying a `landed` stamp while the trunk is red — if false (a crash between the land and the save): a bare re-run re-derives and at most one report is lost, as spec 10 A3 already accepts.
- A5: `returned` at MERGE_RED needs no new `applied` case: a lane already past `dispatched` is already-applied by the existing rule — if false: add the case.
