# The prototype is pinned in chat and proved at LOOK

## Intent
- You asked: rebuild /spec:prototype, keeping v8's light driver and restoring v7's guarantees — v8 refuses to open on both real hosts, crashes on real v7 pins.json, and nothing downstream reads its contract; v7's replay and look stop found real gaps, but the overlay sent 0 of 54 pins; the real loop is the user viewing the app and arguing in chat.
- I will build:
  - `prototype.js` keeps OPEN → ROUND ×N → APPROVED → CONTRACTED → CLOSED with no entry-file check and no overlay: OPEN makes the worktree, runs `setupCommand`, allocates one free app port and prints the boot line; ROUND prints the ready line only when the url answers; the session records each ruling with `prototype.js <stem> pin …`; APPROVED prints every active sentence grouped by route and `contracted --confirmed` needs the user's yes; `drop pN --why` is the amendment path; close is guarded and honest.
  - The contract is `{stem, rounds, pins:[{id, kind, route, given?, note, sentence, round, status}]}`; no selector, states, tests or who; `?proto=` never appears.
  - `/spec:plan` reads the contract at lock: a behaviour pin with no `(pin pN)` AC in this or an earlier locked citing spec refuses the lock by id; look pins are Decisions for LOOK; the queued plan item closes once every behaviour pin is covered.
  - `/spec:run` on a prototype spec appends the pin sentences to the builder and reviewer briefs, runs the host's pin tests in a PIN_TESTS step after REVIEW, then stops at LOOK with the app running from the spec worktree; `close enough` commits, anything else is a FIX round with the reply as the symptom.
  - Pictures are optional (`prototype.picture`), pinned routes only, a reference never a gate. Dead-tree fixes from report-v8.md: commit before the contracted mark is durable, resume refused on differing idea words, doctor's remedy, docs and ADR-0035 brought to the new shape.
  - One `/spec:migrate` op rewrites v7 `status.json`, `pins.json` and `contract.json` to the new shape and trims the `prototype` config block; `readProto` refuses a v7 file naming `/spec:migrate`.
- I will not touch:
  - states.json, stable ids, prototype-side test derivation, a TESTS state, REPLAY with `PROTO_URL`, the ledger, the prototype-line check, a contract review leg, brief stamping and reconcile, DB hooks — none comes back.
  - The plugin version (ADR-0039 D4); `/git:merge`'s `proto/*` refusal; the status screen and its goldens; spec 13's queue work (only the doc rows named in D20 are shared, and this spec lands after it).
  - The pin tests' content beyond what the briefs say: the builder writes them in the host's e2e file and the host's `prototype.e2eCommand` runs them.
- Architecture or behaviour change: yes — ADR-0035's picture per route × state, prototype-derived tests, build REPLAY and review-driven close are replaced by sentences the builder proves with pin tests in a PIN_TESTS step and the user accepts at LOOK (ADR-0043, amending ADR-0035), needs your yes
- Client sign-off: the overlay, pictures and where pin tests run — JJ chose: delete the overlay; pictures optional and never a gate; pin tests run in a separate step before LOOK (given with the brief)

## Goal

A prototype opens on niko-hub and on a Next.js app with only `bootCommand` and `url` in config, every ruling from chat becomes a pin sentence the user confirms before the contract is written, and a spec citing the stem cannot lock without an AC per behaviour pin. The build of that spec proves each pin with a browser test the host runs in its own step, then stops with the app up for the user to look; the prototype records, old and new, read strictly and migrate in one step.
