## Intent

## Goal

A build that did nothing, a plan row that is not on disk and a superseded spec each stop before review, with the reason named. A test that proves nothing is named to the reviewer. No driver commit takes a stray file or a secret into history without saying so. A release cannot print `✅ released` unless staging was green on that commit and production answered after the promote.

## Acceptance Criteria

- **AC-20261105-15-1**: WHEN `run.js` opens a spec whose status is `superseded`, `bogus` or absent THE SYSTEM SHALL exit 2 naming that status (`<missing>` when absent) and `hardened or implementing`, and create no worktree or branch; AND WHEN the status is `hardened` or `implementing` THE SYSTEM SHALL reach BUILD.
- **AC-20261105-15-2**: WHEN `setupCommand` fails on a worktree OPEN just created THE SYSTEM SHALL exit 1 and leave neither the worktree nor the `spec/<stem>` branch; AND WHEN the command is then fixed and the run repeated THE SYSTEM SHALL run setup again before BUILD.
- **AC-20261105-15-3**: WHEN a green gate follows a build that changed only its own spec's status THE SYSTEM SHALL enter REPAIR with a tail naming `nothing changed`, spec-less fix included; WHEN a CREATE or MODIFY row's file is absent, or a DELETE row's file present, or a glob row fails its match rule THE SYSTEM SHALL enter REPAIR with a tail naming each such row and its action; AND WHEN that repeats past `REPAIR_CAP` THE SYSTEM SHALL ESCALATE with `why: gate`, never REVIEW.
- **AC-20261105-15-4**: WHEN a green gate follows a build that added a test passing on the base and `testFileCommand` is set THE SYSTEM SHALL reach REVIEW with a brief naming that file as vacuous, and run red-check once for that tree; WHEN red-check reports an `error` THE SYSTEM SHALL print its `no verdict` line in the brief and reach REVIEW; WHEN `testFileCommand` is not set THE SYSTEM SHALL not run red-check and print no such line; AND WHEN a gate is red THE SYSTEM SHALL not run red-check.
- **AC-20261105-15-5**: WHEN a build edits an existing test file or adds `spec/scripts/x.js` THE SYSTEM SHALL leave them out of red-check's `files`; AND WHEN a build adds `a.test.js`, `b.spec.ts`, `c_test.go`, `d_spec.rb` or `test_e.py` THE SYSTEM SHALL check each.
- **AC-20261105-15-6**: WHEN a gate runs on a spec build whose planned CREATE file is untracked THE SYSTEM SHALL have it in the index as intent-to-add while the host command runs (a `git ls-files`-reading `testCommand` sees it) and SHALL leave untracked every file outside the File Plan; WHEN a planned file is hidden by `.gitignore` THE SYSTEM SHALL print one `⚠️` line naming it and still run the gate; WHEN the git call fails THE SYSTEM SHALL exit 2 without running the gate; WHEN a worktree run with such an entry merges THE SYSTEM SHALL merge with no dirty refusal and the file in the commit; AND WHEN a fix gate runs THE SYSTEM SHALL add no entry.
- **AC-20261105-15-7**: WHEN an in-place spec run reaches COMMIT with an untracked `notes.txt` outside the File Plan THE SYSTEM SHALL commit the File Plan paths and the spec, leave `notes.txt` untracked, and warn `left uncommitted: notes.txt`; WHEN a path was widened at the scope stop THE SYSTEM SHALL commit it; AND WHEN a worktree run reaches COMMIT THE SYSTEM SHALL CONTINUE TO commit the whole tree.
- **AC-20261105-15-8**: WHEN `run.js --fix "x" --in-place` opens with an untracked `notes.txt` THE SYSTEM SHALL reach BUILD; AND WHEN that fix commits THE SYSTEM SHALL commit the files the fix touched, leave `notes.txt` untracked, and warn `left uncommitted: notes.txt`.
- **AC-20261105-15-9**: WHEN `commitAll` stages a fixture with every path rule, every content rule, a binary file, a `secrets-scan:allow` line, `.env.example` and a deleted file THE SYSTEM SHALL commit nothing and return the same `{path, reason, line}` hits as `secrets-scan.js` from tag `spec-v7-final` on that fixture, and a missing tag SHALL fail the test; WHEN a path is in `allow` or `exclude` THE SYSTEM SHALL not report it; WHEN `noVerify` is set THE SYSTEM SHALL commit without scanning; WHEN a spec run or a fix reaches COMMIT with a hit THE SYSTEM SHALL stop at ESCALATE naming every hit with `exclude` first, as a pending question of kind `decision` in a lane; WHEN `exclude` is chosen THE SYSTEM SHALL commit without those paths, keep them on disk and warn `kept out of this commit: <paths>`; WHEN `stage` is chosen THE SYSTEM SHALL commit them and warn `staged on your say-so: <paths>`; WHEN a repair adds a new hit THE SYSTEM SHALL ask again; WHEN a lane's `wip` commit holds a hit THE SYSTEM SHALL still stop at COMMIT; AND WHEN genesis grounds a tree holding a hit THE SYSTEM SHALL commit the rest and print `kept out of this commit: <paths>`.
- **AC-20261105-15-10**: WHEN a lane is open and its worktree runs each of `cherry-pick`, `revert`, `am`, `apply`, `pull`, `fetch`, `tag`, `rm`, `mv`, `update-ref`, `symbolic-ref`, `update-index`, `config`, `remote`, `submodule`, `gc`, `bisect` THE SYSTEM SHALL exit 2; WHEN it runs each v7 `ALLOW` verb, `git add` or `git rebase --continue` THE SYSTEM SHALL exit 0; AND WHEN `git fetch` runs in the main checkout while a lane is open THE SYSTEM SHALL exit 0, and `git reset --hard` there SHALL CONTINUE TO exit 2.
- **AC-20261105-15-11**: WHEN `spec/doctrine.md` and `spec/commands/release.md` are read THE SYSTEM SHALL state that a dismissed AskUserQuestion stops the run and that a dismissed promote question promotes nothing; AND WHEN `spec/agents/reviewer.md` is read THE SYSTEM SHALL state that a new test passing without the production change is blocking unless it covers a `SHALL CONTINUE TO` criterion, and that deleting the test behind such a criterion is blocking, for an earlier spec's criterion too.
