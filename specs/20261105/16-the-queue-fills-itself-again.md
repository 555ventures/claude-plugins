# The queue fills itself again

## Intent
- You asked: Restore the queue's self-filling and fanout's ordering, as ports from spec-v7-final. Then, on the status queue: "Why it does not show type. Like fix, plan, run, etc etc with emoji? Also, why we have spec:fix and spec:run --fix?" Agents mainly write the queue, and you check it often to see what tasks exist and where the work stands.
- I will build:
  - A fill in `lib/queue.js`, worked out on every read and never stored: every unfinished brief and open ad-hoc spec joins the queue, so `list` shows the same work the status screen shows.
  - `next` that delegates to the derivation, so it offers the real next command and never a blocked spec when an unblocked one exists.
  - Bare fanout that takes every startable spec, queued or not, in queue order, with a queued brief standing for its specs.
  - Fanout's brief rules: a shared brief waits for its sibling, and a brief dependency ends the batch.
  - The door again: unknown flags refused on every subcommand and on a bare fanout, a spec path with no file refused, one brief queued once however spelled, a vanished spec's item retired, a ticked item's gate ended.
  - `list` rows with v7's columns and flags plus a type column, `show`'s header, the ambiguous-ref and already-done refusals. Rows are proven against v7 on the same items, not byte for byte.
  - Type on every queue row: 🏃 run, 📝 plan, 🧪 prototype, 🔧 fix, 📌 decide, on `queue list` and the status screen.
  - A `🔨 in progress` marker on rows being worked on, on both screens.
  - `list --json` carrying `type`, `ref` and `inProgress`.
  - `/spec:fix` as the only fix command: fanout lanes call it, and `--fix` leaves the `/spec:run` docs and stays private to `run.js`.
  - A warning on the status screen for an old-format queue, naming `/spec:migrate`.
- I will not touch:
  - The stored shape: the file stays `{version: 3, seq, items[]}`, so no `/spec:migrate` step.
  - `--at` and `--when`: both stay cut (`architecture.md:402`, ADR-0041 §1); `move` does `--at`'s job. Each now gets the unknown-flag refusal instead of landing in the payload.
  - The near-duplicate refusal on `add` and `--distinct`: the 0.35 score is suspicion, not evidence (`commands/queue.md`), and `groom` already reports it. `add` keeps the exact-duplicate refusal.
  - The archive file: done rows stay in `spec-queue.json`, where `show` and the `— N done` count already read them. Contract §3 stops listing the file.
  - `next`'s lead lines (`🛣️ <lane>`, `⚠️ no lane`): `next` stays a line to paste (spec 12 AC-4).
  - Fix lanes scheduled by the files they name: lanes run in parallel whatever their File Plans share and rebase settles it (`architecture.md` §5).
  - In-batch rolling, `implementing` as a lane, the red-main repair lane: cut on purpose (spec 07 D1, D5; `architecture.md:121`).
  - REPORT listing what the batch queued (needs new fanout state; `list` shows it), `SendMessage` resume (run state carries a lane), the per-step worktree refusal (a lane never runs fanout), `stops.<key>` lines (no v8 code writes them).
  - `--pick` details, dirty-root untracked counting, `area`/`date` in `--json`, the words `queued …`, `done …` and `did you mean`: cosmetic, no wrong result.
  - `run.js` (spec 15), including its `--fix` refusal words, and `doctor.js` and `migrate.js` (spec 17). Doctor's hygiene list is spec 17's D13; the status footer keeps v7's `(/spec:doctor)` words for the goldens.
  - `plan.js`: lock adds nothing to the queue and its `Next:` line stays. `queue add` still places an unqueued spec.
  - `groom`, `next` and `show`: no type column or marker. `next` stays a bare line to paste and `groom` stays v7's bytes.
- Architecture or behaviour change: yes — ADR-0044 amends ADR-0041 §1 and §6 and ADR-0042: the file holds what was placed, by a user or an agent, and readers derive the rest. Bare fanout builds specs nobody queued, the screens carry a type and a progress marker v7 never had, and `docs/v8/design.md:6-7` changes because agents mainly write the queue. You said yes on 2026-11-06.
- Client sign-off: may the fill be stored, what does bare fanout build, and do the marker and `--json` fields belong here — memory-only fill, every startable hardened spec whether queued or not, and yes to both additions.

## Goal

On a repo with open briefs and specs, `queue next` prints the real next command and `queue list` shows the same work the status screen shows, with each row's type and what is in progress. Reading the queue writes nothing, so the file never holds a second copy of spec state. Bare fanout builds what is startable in v7's order and stops where v7 stopped, and it says `drained` only when nothing is open. Mistyped flags, missing spec paths and old-format queue files stop with their remedy instead of giving a quiet wrong answer. A fix has one command, `/spec:fix`.
