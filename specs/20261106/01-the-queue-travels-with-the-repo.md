# The queue travels with the repo

## Intent
- You asked: Sync the queue across my 3 machines by making placed queue items committed files, one per item, under specs/queue/. Each item has a collision-free id (date + 4 hex) and its own rank, so a move changes one file. Every queue write commits that one path. Done on a placed prompt deletes its file; a ticked filled brief or spec keeps a tiny tombstone. All queue reads and writes go through the main checkout, never a lane branch, so an abandoned lane loses nothing and queue files never enter a lane's diff. Take a lock around those commits so parallel lanes cannot collide on the git index. Remove .git/spec-queue.json with format v4 and one /spec:migrate step that moves open items and drops done prompt rows. Add an ADR that amends the common-dir decision.
- I will build:
  - Format v4: one JSON file per placed item at `specs/queue/YYYYMMDD-xxxx.json` with its own rank and no shared sequence, owned by `lib/queue.js`, its storage in a new `lib/queue-files.js`.
  - Every queue read and write resolves the main checkout from any worktree; every write takes one machine-wide lock and commits only its own paths on trunk.
  - Queue commits cost no gate run and break no landing: queue paths leave the gated tree and every build diff, and `lib/land.js` and `/spec:release` treat a queue-only trunk move as no move.
  - `/spec:migrate` turns each machine's old queue file into item files, merging with items already pulled, and removes the old file.
- I will not touch:
  - Pushing, pulling or fetching (no script does any), a custom sync ref, and machine-local state: `spec-fanout.json`, `*.run/`, the gate cache, `spec-release.json`.
  - What the queue means: the fill, `after` gates, types, `next`, `list`, `groom` and 05's brief close, except that ids get longer.
  - This repo's own `.git/spec-queue.json`: the build never runs `--apply` here; you migrate each machine after the merge.
- Users will notice: `git pull` brings the other machines' queue; each queue change is a small `chore(queue): …` commit on trunk, pushed before switching machines; `/spec:queue` writes refuse while the main checkout is off trunk or mid-merge; ids read `20261107-a3f9`, not `q336`.
- You lose: a private per-machine queue (its text becomes repo history) and `qN` ids.
- Architecture or behaviour change: yes — the queue moves from an untracked git-dir file to tracked files on trunk (ADR-0045), and queue writes refuse in some checkout states, needs your yes
- Client sign-off: breaking change to the queue's home and format — yes, approve; queue writes on a side branch or mid-merge — refuse with instructions; queue text visible to everyone on each repo — accept, block secrets (all 2026-11-06); [NEEDS CLARIFICATION: a run's own queue write while the main checkout is off trunk (D6)]

## Goal

Run `git push` on one machine and `git pull` on another, and `/spec:queue list` shows the same items in the same order on both. Parallel lanes keep landing with no extra full-suite gate and no failed fast-forward, an abandoned lane loses no queue item, and no `.git/spec-queue.json` remains after `/spec:migrate`.

## Decisions

| ID | Decision | Why |
|----|----------|-----|
| D1 | The queue's home is tracked files under `specs/queue/`: ADR-0045 (accepted 2026-11-06) amends ADR-0042 (the `{version: 3, seq, items[]}` file) and ADR-0044 (what "the file" is) and overturns specs/20260823/08 D1; ADR-0042's single owner and strict read and ADR-0044's "holds what was placed, readers derive the rest" stand. No script pushes, pulls or fetches, there is no custom sync ref, and run and fanout state stay machine-local. | The common dir never leaves a machine. A ref fetched on read would put the network on every read, and `reconcile` would falsely close an item arriving before its unpushed spec. |
| D2 | An open item is `{version: 4, id, rank, kind, type?, spec?, payload, added?, after?}`, a tombstone `{version: 4, id, kind, payload, done}`; `seq` goes. The id is the file stem `YYYYMMDD-xxxx` (local date, 4 random hex, retried while that file exists). `rank` is a decimal string compared numerically, ties broken by id: append is floor(last) + 1, `--top` ceil(first) - 1, and between two items their exact BigInt midpoint, so nothing is ever renumbered. | No shared counter for two machines to race, and a move changes one file. A float runs out after ~50 moves into one gap. A same-day id collision (1 in 65,536) surfaces as a git add/add conflict. |
| D3 | New `lib/queue-files.js` (the wip's, required only by `lib/queue.js`) holds paths, the strict read, rank maths, the D5 check, the lock and the commit; `lib/queue.js` keeps the meaning and its 200-line pin. Every read and write resolves the main checkout with `git.mainRoot(root)` (run.js:37 moved into `git.js`, joined with `rev-parse --show-prefix` for `--root`), and `fill` and `reconcile` read spec state there, so `isMain` and `queuePath` go. `Q.write` and `Q.place` go: the write surface is `add`, `tick`, `hold`, `move` and `done`, which absorb the CLI's splice-and-write and place-then-tick. `lib/next.js` `overlay` calls `Q.read` instead of parsing the file, still off in a linked worktree. The AC-20261105-12-6 owner list gains `lib/queue-files.js`. | One owner (ADR-0042): the CLI's two direct writes are the only code outside it that knows the layout. A lane's copy of `specs/queue/` is never read or written, so an abandoned lane holds nothing. |
| D4 | Strict reader: any `<git-common-dir>/spec-queue.json` refuses every read, naming `/spec:migrate` (the status screen keeps its migrate line). Every `specs/queue/*.json` must parse, carry version 4 and name its own stem, else the refusal names that file; `.tmp` names are skipped; no directory means no items. | ADR-0042: one migration, no tolerant reads. A git conflict marker lands in an item file and must stop the reader. |
| D5 | A write refuses (exit 2, naming the state and its remedy, nothing written) when the main checkout is not on trunk, is detached, or is mid-merge, mid-rebase, mid-cherry-pick or mid-revert. Reads never refuse on git state; `queue next` and `list` warn on stderr when it is off trunk. [asked: refuse with instructions] | git refuses a partial commit during a merge, and a commit on a side branch would strand the item there. |
| D6 | A write a driver makes as a side effect — `run.js` park and advisories, `lib/land.js`'s spec tick and 05's brief tick, `fanout.js` `Q.hold`, `plan.js` lock's plan-item tick, `prototype.js`'s plan item — that refuses under D5 writes nothing; its report gains one `⚠️ not queued — <state>; on <trunk>: /spec:queue add …` (or `done …`) line and the run goes on. [NEEDS CLARIFICATION: confirm warn-and-carry-on over stopping the run or committing on the branch] | v8's `--in-place` builds on a side branch by design (run.js:80), and stopping a finished run over bookkeeping strands it. A spec item still closes through `reconcile` once its done spec reaches trunk. |
| D7 | The lock is `<git-common-dir>/spec-queue.lock/`: the gate slot's pid-file directory (`takeSlot`, lib/host.js) generalised to a name and a limit of 1, 100 ms poll, dead pids cleared, and a live holder past 60 s refusing by pid; never nested. Under it a write checks D5, reads fresh, passes each new file through `git.scanFile` (now exported; a hit refuses naming the rule, never the text) [asked: accept, block secrets], writes tmp then rename, and runs `git add -- <paths>` and `git commit -q --no-verify -m "chore(queue): <verb> <id>" -- <paths>` in the main checkout. The same lock wraps every other script commit to that index: `land()` from its final trunk check through `mergeBack`, its ticks and 01's stub sweep; run.js COMMIT's `commitAll` in place; `plan.js` lock's commit; `migrate --apply`'s commit. | Locking only the queue writers would still collide with a merge on `index.lock`. There is one index per machine, so one lock. A `-- <paths>` commit leaves other staged and edited files as they were (A1). |
| D8 | `git.js` owns `QUEUE_DIR = 'specs/queue'`. `git.diff` and `git.changedFiles` exclude it, and `host.js` `OVERLAY` gains it, so `treeSha`, the gate cache, run.js's scope and nothing-changed checks, `specEdits`, red-check and 04's criteria read never see it. | A queue commit between gate and landing must not change the gated tree, or every landing re-runs the full suite. |
| D9 | New `git.queueOnly(from, to)` is true when every changed path is under `QUEUE_DIR`. In `land()` a queue-only trunk move is rebased onto and gated again (a cache hit under D8) without counting toward the three-move refusal, and the final `moved` check and `mergeBack` run inside the D7 lock. `release.js --promote` accepts a record whose sha equals HEAD or is `queueOnly` to it. | land.js:38-40 and release.js:68 refuse on any trunk move, and queue commits would make that routine. Under `ff-only`, a local write between the check and the merge would fail the fast-forward. |
| D10 | `reconcile` never writes: its `done` stays in memory, so an item that arrives before its spec reads closed on that machine and comes back when the spec arrives. Dedupe is exact match by key (a brief by number, a spec by path, a prompt by type + spec + payload): the first in rank order is kept, the rest hidden, and any write on an item deletes its open twins in the same commit. `done` on a prompt deletes its file. `done` on brief or spec work writes a tombstone only when the fill would bring the work back, else deletes the file. `done` on a filled item is one write. | Your rule: prefer delete. A tombstone exists only to keep "comes back last" (lib/queue.js:113-114). The same item added on two machines reads as one and closes as one. |
| D11 | `/spec:migrate` is the only converter. A version 1-3 file becomes one item per open row, ranked after any committed item in stored order, with every field kept and the id dated from `added` (today when absent). Done prompt rows are dropped, done brief and spec rows follow D10, and a row matching a committed open item by D10's key is skipped. The old file is deleted last, `backup()` keeps it, and one commit is made: `chore(spec): migrate queue to v4`. Traps: `v7Pending` (migrate.js:294) must exclude every old queue version, an unparseable old file refuses instead of planning nothing, and `--apply` refuses outside the main checkout or under D5. | Each machine holds a different queue, so they merge, never overwrite. Today a v3 file would tag `spec-v7-final` and delete `spec-run-cache`, and `readJson` returns null on bad JSON, the false idempotency 6f2858fe fixed. |
| D12 | `genesis.js` drops its `Q.add` loop (line 146). `spec/doctrine.md` § Files, `spec/commands/queue.md` and `migrate.md`, `docs/v8/interface-contract.md` §3 and §7, and `docs/v8/architecture.md` (§2 row, MERGE row, queue.js paragraph) name `specs/queue/`, version 4, the lock and push-before-switching. No test is deleted, and a changed test keeps every AC-ID it cites. | The fill lists every unfinished brief (ADR-0044; 05 D5 keeps a done brief with open steps), and genesis's trunk is not configured yet. The contract docs are what builders read (ADR-0037). ADR-0048's gate keeps cited criteria. |

## Acceptance Criteria

- **AC-20261106-01-1**: WHEN two real clones of one bare origin each add, move and tick items through `queue.js`, then push and pull with plain git THE SYSTEM SHALL print identical `list --json` on both with no conflict and no script having pushed, pulled or fetched; commands and output recorded in `<spec>.run/evidence.md`.
- **AC-20261106-01-2**: WHEN a real lane worktree runs a mark that queues an item THE SYSTEM SHALL commit it on trunk in the main checkout, leave `git status --porcelain` clean there and the lane's diff free of `specs/queue/`; WHEN that lane is abandoned and its worktree removed the item SHALL still be listed.
- **AC-20261106-01-3**: WHEN queue-only commits land on trunk while `land()` gates a lane, three or more times, under `ff-only` THE SYSTEM SHALL land it with `cached: true` gates and no refusal; WHEN a non-queue commit moves trunk three times it SHALL refuse as today.
- **AC-20261106-01-4**: WHEN an item is added or moved THE SYSTEM SHALL change exactly one path in one commit, with `--top`, append and 200 moves into one gap all keeping the asked order; WHEN two clones append at the same rank both SHALL list them in id order.
- **AC-20261106-01-5**: WHEN `done` closes a placed prompt THE SYSTEM SHALL delete its file; WHEN it closes unfinished brief or spec work, filled or placed, it SHALL leave one tombstone and list the work last; WHEN the work is finished it SHALL delete the file; WHEN one item was added on two clones it SHALL list once after the pull and close as one commit.
- **AC-20261106-01-6**: WHEN a `/spec:queue` write runs with the main checkout on another branch, detached, mid-merge, mid-rebase, mid-cherry-pick or mid-revert THE SYSTEM SHALL exit 2 naming the state and remedy and change nothing; WHEN `list` runs then it SHALL print the items and, off trunk, a warning.
- **AC-20261106-01-7**: WHEN an in-place run on a side branch parks, queues advisories or merges THE SYSTEM SHALL finish its step, write no queue file and print the D6 line with the command to run on trunk.
- **AC-20261106-01-8**: WHEN a write runs during an in-place run on trunk with uncommitted and staged edits THE SYSTEM SHALL commit only the queue path, leave those edits and staged files as they were, and not report the queue path at GATE.
- **AC-20261106-01-9**: WHEN four processes write while `land()` merges in the main checkout THE SYSTEM SHALL land every write with no `index.lock` error; a dead holder's pid SHALL be cleared, and a live holder past 60 s SHALL refuse naming it.
- **AC-20261106-01-10**: WHEN HEAD moved since the green staging run by queue commits only THE SYSTEM SHALL promote; WHEN any other path changed it SHALL refuse as today.
- **AC-20261106-01-11**: WHEN `.git/spec-queue.json` exists THE SYSTEM SHALL refuse every queue read naming `/spec:migrate` and the status screen SHALL offer it; WHEN an item file is invalid JSON, another version or misnamed the refusal SHALL name that file.
- **AC-20261106-01-12**: WHEN `--apply` runs on a version 3 file THE SYSTEM SHALL write one file per open item in stored order with every field kept, drop done prompt rows, keep tombstones only under D10, delete the old file, keep a backup and commit once, tag nothing and keep `spec-run-cache`; run on a copy of this repo's real file, counts before and after recorded in `<spec>.run/evidence.md`.
- **AC-20261106-01-13**: WHEN `--apply` runs again THE SYSTEM SHALL print `nothing to migrate`; WHEN a second clone pulls the first's migration and migrates its own file it SHALL add only items not already there, after the existing ranks; WHEN it runs off trunk, in a linked worktree, during a live fan-out or on an unparseable file it SHALL exit 2 and change nothing.
- **AC-20261106-01-14**: WHEN an item's text matches the secrets scan THE SYSTEM SHALL refuse naming the rule without echoing the text, leaving no file or commit; WHEN the host has no git `plan.js lock` SHALL lock with no queue and no error.
- **AC-20261106-01-15**: WHEN `specs/queue/` holds items THE SYSTEM SHALL report nothing for them in `readSpecs`, `status`, `doctor`, 01's stub sweep or 04's criteria read; an item whose spec has not arrived SHALL be hidden without storing that; genesis SHALL write no item file; and the D12 docs SHALL name `specs/queue/` and version 4, never `spec-queue.json` as the live store.

## Assumptions

- A1: `git commit -- <paths>` leaves other staged files staged, is refused mid-merge, and commits a deleted path (documented git; not run here, because the worker-git hook blocks git in this session) — if false: commit through a scratch index plus an index refresh, under the same lock.
- A2: Only scripts write `specs/queue/`, and no host test reads it, so D8 hides nothing real — if false: refuse at GATE on any lane change under `QUEUE_DIR`.
- A3: Every host pushes trunk directly, with no PR-only protection on it — if false: queue commits cannot reach that host's origin; ask before upgrading it.
- A4: One small commit per queue write, beside 01's stub commit, is acceptable trunk noise, and the main checkout is never bare — if false: batch a landing's ticks into its stub commit.
