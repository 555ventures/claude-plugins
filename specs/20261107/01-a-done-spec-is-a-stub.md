# A done spec is a stub; history holds its text

## Intent
- You asked: Do you really need to keep track of decisions all the time? Why do you keep them? Why can you not stop them from piling up — done and superseded specs become stubs at merge, the sweep is its own trunk commit, a fix hydrates the worktree copy from git, a one-time sweep removes the `[retired:]` tags, and the prose that sends the planner and the reviewer to old spec bodies goes.
- I will build:
  - One owner of the stub shape, `spec/scripts/lib/stub.js`: a done or superseded spec on disk is its frontmatter plus `text: <sha>` and `acs: [ids]`, its title and its `## Goal`; everything else is read with `git show <sha>:<path>`.
  - The sweep: `run.js` FINISH and `fanout.js` `finalize` rewrite every done or superseded spec that is not yet a stub and commit only those paths as one `chore(spec): stub …` commit, after the gate, never inside a build.
  - A fix on a stub: `run.js` OPEN writes the full text from `text:` into the copy the lane builds on; the spec-edit check, the reviewer's "spec text edited" line and the revert compare against that text; the sweep after the merge stubs it again with the new sha.
  - Every machine reader keeps working on a stub: brief state, gates, queue reconcile, the status screen, doctor, and `plan.js lock`'s pin coverage (which now reads `acs:` on a stub).
  - The prose that sends `/spec:plan` step 1 to the brief's done specs and the reviewer to earlier specs' criteria is deleted, and the contract docs describe the stub.
- I will not touch:
  - Draft, hardened and implementing specs: their text stays whole, and a build still may not edit any spec but its own.
  - Frontmatter semantics: `status`, `brief`, `depends_on`, `superseded_by`, `prototype`, `architecture`, `breaking` and every other key stay as they are; a stub keeps all of them (ADR-0041 §3 still holds: a spec's state is its frontmatter).
  - What a build commit or merge commit holds: the full text, `## As built` included, lands exactly as today; the stub is one commit later.
  - The queue (ADR-0044, ADR-0045), run sidecars, briefs, ADRs, `docs/canonical/` (v7 canon; its `[retired:]` paragraph is a v7 leftover, out of scope with the rest of that cleanup), stale-unbuilt-spec state and the run cache.
- Users will notice: `specs/` shrinks from ~8.6 MB to frontmatter-and-goal stubs; `git log -p` and `git show <sha>:<path>` are where a finished spec's Decisions, File Plan, ACs and As built live; one `chore(spec): stub …` commit follows every merge that finishes a spec or lands a fix on one.
- Architecture or behaviour change: yes — what a spec file holds after it is done changes from the whole record to a pointer into history; confirmed 2026-11-07, recorded as ADR-0046 (no accepted ADR is overturned)
- Client sign-off: when existing finished specs shrink — automatically at the next merge in every project; new ADR-0046 — yes; one doctrine sentence — yes; breaking — no

## Preparation

Readers of a done spec today, by what they read: `lib/work.js` `readSpecs`/`readBriefs` (frontmatter: status, brief, depends_on, superseded_by; File Plan paths, used only for lane admission among hardened specs), `work.gateWhy` and `fanout.js` `unmet`/`trunkStatus` (status), `lib/queue.js` `reconcile` and `queue-rows` groom (status), `lib/next.js` and `status.js` (frontmatter and File Plan paths), `doctor.js` (status), `lib/state.js` `specsCiting` (`prototype:` line) and `plan.js` `pinCoverage` (the AC text of every hardened, implementing or done spec citing the same stem, for its `(pin pN)` cites — the one reader of a done spec's body). `run.js` reads a done spec's body only in a bound fix lane (`--fix` on a done spec): Intent/Goal, Decisions, ACs, Assumptions, File Plan (`outsideFiles`), `architecture:` and `prototype:`, and writes `## As built` and ruling rows into the worktree copy.

Real use (32 days, 1,225 sessions on this box): a done spec's body was read in 1.7 % of sessions, 0.4 % of tool output; every such read is answerable by `git show`. This repo: 320 specs, 304 done, 12 superseded, median 24 KB; 95 done specs carry ~439 `[retired: …]` tags and no script writes them any more. The last full text of a merged spec is in the merge commit (worktree run), the `chore(spec): <stem> done` commit (fanout) or the build commit (in place) — never the lock commit, which lacks As built and rulings. So `text:` names the commit the sweep sits on, and one sweep names one sha for every stub it writes.

`specEdits` compares the own spec's Decisions against `git show <base>:<own>`; a hydrated copy would differ from a stub base in every row, so the comparison must follow `text:`. `fanout.test.js` asserts `no done commit` with `/chore\(spec\):.*done/` and that a landed sha is the main head; `run.test.js` reads `## As built` from `main:<spec>` after a run. Those tests change with the behaviour.

## Goal

A finished spec stops being a 24 KB file nothing reads: at merge it becomes a stub that keeps what the pipeline derives from (frontmatter, title, goal, AC ids) and a `text:` sha for everything else, in its own trunk commit. A fix on it works from the full text again and leaves a stub behind. The first sweep on this repo stubs its 316 finished specs and with them the `[retired:]` tags; the planner and the reviewer are no longer told to read old spec bodies.

## Decisions

| ID | Decision | Why |
|----|----------|-----|
| D1 | The stub shape, owned by a new `spec/scripts/lib/stub.js` (`isStub(frontmatter)`, `stubOf(text, sha)`, `fullText(cwd, rel, sha)`, `sweep(root, {dry})`; no CLI): the original frontmatter block verbatim, in order, with `text: <sha>` and `acs: [...]` set (replaced when present), then a blank line, the `# <Title>` line, a blank line and the `## Goal` section verbatim (omitted when the spec has none). `acs:` lists every `- **AC-…**` id of the full text in order, each followed by its `(pin pN)` cites when it has any (`AC-20261105-14-3 (pin p2)`), `[]` when none. `isStub` is a `text:` value of 7–40 hex characters. | The frontmatter is what every reader derives state from (ADR-0041 §3); the Goal is the one sentence the release changelog and a person need (ADR-0039 D4 dissent); the AC ids let `git grep AC-…` find the spec a test names; the pin cites keep `plan.js lock` honest without reading history. One owner, like `lib/queue.js` for items (ADR-0042). |
| D2 | `text:` is the sha of HEAD in the checkout where the sweep runs, read before the stub commit, so the stub commit's parent holds the full text. `fullText` runs `git show <sha>:<rel>` in the given checkout (a worktree shares the object store); a sha the clone does not hold is a refusal naming it (`<rel> names text <sha>, not in this clone — git fetch --unshallow, then re-run`, exit 2). | The last full text is in the merge, the done commit or the build commit — the commit the sweep follows — never in the lock commit. `git show` by sha is stable across rebases of nothing: trunk history is never rewritten here. |
| D3 | `sweep(root)` walks `specs/**/*.md` (not `.run/`), and for every spec with `status` `done` or `superseded` that is not a stub, is tracked and has no uncommitted change, writes `stubOf(text, head)`; then `git add -- <paths>` and `git commit -q -m "<subject>" -- <paths>` in that checkout. The subject is `chore(spec): stub <id>` for one spec and `chore(spec): stub <n> specs` for more, never containing the word `done`. Nothing to stub commits nothing. `{dry: true}` returns the paths and the count of `[retired:` occurrences they carry and writes nothing. | A sweep must be idempotent and must not fold a user's uncommitted edit or an untracked draft into a machine commit; committing by path is how `finalize` already commits the done line. `fanout.test.js` pins that a fix lane makes no `chore(spec): … done` commit, so the subject avoids the word. The dry run is the evidence for the one-time sweep (AC-8). |
| D4 | Where the sweep runs: `run.js` `finish()` calls `stub.sweep(mainRoot)` after the trunk gate and the status write, before the worktree is removed; `fanout.js` `finalize()` calls it after the done commit, before `worktreeRemove`. Both run it for every lane kind (a fix lane too: its hydrated spec needs re-stubbing). The sweep commit is never gated: no test reads spec text, and the next merge gates its own tree. The `landed as <sha>` line and `text:` name the same sha (the merge); the stub commit is the one after it. | A lane may not edit another spec file (`specEdits`), so the sweep cannot be part of a build: it is the trunk's own bookkeeping, like the done commit. After the gate, so a red trunk never carries a sweep (`MERGE_RED` holds `finalize` until `gate-repaired`). |
| D5 | What the sweep covers: every done or superseded spec not yet a stub, so this repo's 316 finished specs are stubbed by the first merge after this spec lands and every host is stubbed by its next merge, in one `chore(spec): stub N specs` commit; `/spec:migrate` gains no step. Recorded as ADR-0046. [asked: existing specs shrink automatically at the next merge, in every project — not via /spec:migrate] | The one-time sweep is nothing but the first sweep, there is no command to remember (ADR-0045 §6 shows how migrations go stale across hosts), one shape exists everywhere, and the stub is lossless (`git show`). |
| D6 | A fix on a stub: `run.js` `open()` with `state.fix` and `isStub` writes `fullText(wt, rel, text)` to the copy the run builds on — the worktree copy it makes (`!why`), the lane's own copy, or the file in place — and records `state.hydrated = <sha>`. The hydrated text keeps its own status line (done at that sha). `specEdits`, `outsidePlan` and `restoreFromBase` resolve the base copy of the own spec through one helper `baseSpecText(state, ctx)`: `git show <base>:<own>`, and when that is a stub, `fullText(wt, own, stub.text)`. The reviewer brief gains, when `state.hydrated` is set, the line `The spec file in the diff grows from its stub to its full text (hydrated from <sha> for this fix); that is bookkeeping, not a finding.` next to the existing status-line sentence. The builder and reviewer briefs read Decisions, ACs, Assumptions and File Plan from the hydrated copy as today. The fix commit carries the full text with its `## As built` bullets; the next sweep (D4) stubs it with the merge sha. | The fix lane needs the File Plan to tell outside files, the Decisions to brief and to guard, and a place to append As built; `git show` gives all of it. Comparing a hydrated copy with a stub base would call every Decisions row an edit and escalate `spec-edit`; following `text:` keeps the guard exact. A reviewer who sees a 24 KB spec appear in the diff needs to be told why, as it is told about the status line. |
| D7 | `plan.js` `pinCoverage` cites `(pin pN)` from a citing spec's body ACs when it has any, else from its frontmatter `acs:` entries (D1). `lib/state.js` `fmScalar` already parses `[AC-x-1, AC-x-2 (pin p3)]` as a list; no parser change. | The lock's coverage rule (ADR-0043) must see a done citing spec's pins without reading history; the stub carries exactly that. |
| D8 | Prose: `spec/commands/plan.md` step 1 drops "and the specs already marked `brief: NN`" and reads "Read the brief and its specs that are not yet done (a finished spec's text is `git show <text sha>:<path>`), then `ls docs/adr` …". `spec/agents/reviewer.md` drops ", even when the criterion belongs to an earlier spec" (the sentence ends at "is `blocking`"). `spec/doctrine.md` § Files gains one sentence after the specs path: "A done or superseded spec is a stub (frontmatter, title, goal, `text: <sha>`); `git show <sha>:<path>` prints its text." `docs/v8/interface-contract.md` § spec doc and `docs/v8/architecture.md` (the `specs/…` state row, the As built note and the lib list) describe the stub, `text:`, `acs:`, the sweep commit and the fix hydration. `tests/run.test.js` AC-20261105-15-11 drops its assertion on the deleted clause (ADR-0037: a retired phrase is checked once at review, not pinned). | A planner cannot read bodies that are gone, and a reviewer judges a deleted test by the test it sees in the diff, not by a criterion in a spec it cannot open; the contract docs are what the suite pins (ADR-0037). | D9 | Readers that need no change, pinned by tests on stub fixtures: `work.readSpecs`/`readBriefs` (brief state from members' frontmatter), `gateWhy`, `fanout` `unmet`, `queue.reconcile`, `status.js` (`--json` `specs[].filePlan` is `[]` for a stub), `doctor.js`, `specsCiting`. `writeStatus` works on a stub unchanged. | The stub keeps the whole frontmatter, which is all they read; the test proves it rather than asserting it. |

## Acceptance Criteria

- **AC-20261107-01-1**: WHEN `stubOf` is given a done spec's text and a sha THE SYSTEM SHALL return its frontmatter block verbatim plus `text: <sha>` and `acs: [<every AC id in order, each with its (pin pN) cites>]`, the `# <Title>` line and the `## Goal` section, and nothing else; and `stubOf(stubOf(t, s), s2)` SHALL equal `stubOf(t, s2)` except for `text:`.
- **AC-20261107-01-2**: WHEN `sweep(root)` runs in a repo holding a done spec, a superseded spec, a hardened spec, a done spec with an uncommitted edit and an untracked done spec THE SYSTEM SHALL rewrite only the first two, commit only those two paths as `chore(spec): stub 2 specs` with the pre-sweep HEAD as each `text:`, leave the others byte-identical and uncommitted, and a second `sweep(root)` SHALL commit nothing.
- **AC-20261107-01-3**: WHEN `fullText(cwd, rel, sha)` is called with the sha a stub names THE SYSTEM SHALL return the full text committed at that sha; and WHEN the sha is not in the clone THE SYSTEM SHALL throw a refusal (exit 2) naming the path and the sha.
- **AC-20261107-01-4**: WHEN a stubbed done spec is read by `work.readSpecs`, `readBriefs`, `gateWhy`, `queue.reconcile`, `status.js --json`, `doctor.check` and `specsCiting` THE SYSTEM SHALL report the same status, brief, dependencies, gate verdicts and `prototype:` as for the full text (`filePlan` `[]`).
- **AC-20261107-01-5**: WHEN `/spec:run <spec> --fix "<symptom>"` opens a stub (in a lane worktree, a fanout lane and `--in-place`) THE SYSTEM SHALL write the text at `text:` into the copy the run builds on, brief the builder with its Decisions, ACs and File Plan, report an edit of one Decisions row as `spec-edit` and an unchanged table as none, print the hydration line in the reviewer brief, and commit the full text with its `(fix: …)` As built bullet; and WHEN the run is not a fix THE SYSTEM SHALL refuse a done stub as today (`already done`).
- **AC-20261107-01-6**: WHEN an in-place `/spec:run` or an in-place fix on a spec finishes THE SYSTEM SHALL leave `HEAD` as `chore(spec): stub <id>` whose parent is the build or fix commit, the working copy a stub whose `text:` is that parent, `git status --porcelain` empty, and the run report unchanged but for that commit.
- **AC-20261107-01-7**: WHEN fanout lands a spec lane or a bound fix lane THE SYSTEM SHALL print `landed as <merge sha>`, commit `chore(spec): stub …` on trunk right after the done commit (or the fix commit) with `text: <merge sha>`, and make no commit matching `chore(spec): .* done` for a fix lane; and WHEN the trunk gate is red THE SYSTEM SHALL make no stub commit until `gate-repaired`.
- **AC-20261107-01-8**: WHEN `sweep(root, {dry: true})` runs on this repo at build time THE SYSTEM SHALL list every done and superseded spec (316 at plan time) and count the `[retired:` occurrences they carry (~439); the builder records both numbers in `specs/20261107/01-a-done-spec-is-a-stub.run/evidence.md`; and WHEN a fixture spec carrying `[retired:` tags is swept THE SYSTEM SHALL leave `grep -rl "\[retired:" specs/` with zero hits.
- **AC-20261107-01-9**: WHEN `grep -rn "specs already marked" spec/commands/plan.md` and `grep -rn "belongs to an earlier spec" spec/agents/reviewer.md tests/run.test.js` run THE SYSTEM SHALL return zero hits, and `spec/doctrine.md`, `docs/v8/interface-contract.md` and `docs/v8/architecture.md` SHALL each contain `text:` beside `git show`.
- **AC-20261107-01-10**: WHEN `plan.js lock` runs on a `prototype:` spec whose only cover for pin `p3` is an earlier done citing spec that is now a stub with `acs: [AC-X-01-2 (pin p3)]` THE SYSTEM SHALL lock, and WHEN that stub's `acs:` lacks the cite THE SYSTEM SHALL refuse naming `p3`.
- **AC-20261107-01-11**: WHEN a brief's member specs are all stubs THE SYSTEM SHALL report the brief `done` and an `after: {brief}` gate met, and WHEN one member is hardened THE SYSTEM SHALL report `in-flight`.

## Assumptions

- A1: No host test reads `specs/**` text, so a stub commit changes no gate result — if false: that host's next merge gate goes red on the sweep, which `/spec:fix` repairs; the sweep still runs after the gate.
- A2: Every host's trunk history is complete (no shallow clone) where a fix on a stub runs — if false: D2's refusal names the fetch; nothing is hydrated from a missing object.
- A3: `[retired:` tags appear only in done specs' bodies here (95 files, all `status: done`) — if false: a tag in a hardened spec stays until that spec is done and stubbed.
- A4: A fix lane is the only build that opens a done spec — if false (a future command that edits a done spec): it hydrates through `fullText` or reads history itself; nothing writes into a stub but `writeStatus` and the sweep.
