# The host declares its runtime once

## Intent
- You asked: "spec:prototype does not work as I expected… v7 prototype was working perfectly fine. Something has changed on v8… I want to know is architecturally sound, robust, clean solution."
- I will build:
  - One config block, `runtime`, declares how the app boots, when it is ready, which url to show and the one idempotent env/data command; `/spec:migrate` moves the old `prototype.bootCommand`/`url`/`publicUrl` there and strict readers refuse the old shape.
  - One app-lifecycle seam, `lib/app.js`, that starts the app detached, waits for the host's ready check, keeps the pid in the driver's state, restarts a dead or stale app and stops it; `prototype.js` and `run.js` both drive it, and no step ever prints a boot line for the session to type.
  - An environment stage: a fresh prototype worktree gets the `.worktreeinclude` files and `setupCommand` exactly as a run worktree does, and `runtime.envCommand` runs once per worktree before the app's first boot.
  - `closed` and every ending of a run stop the app they started; `host.withApp`, `host.allocApp`, `state.bootCommandOf` and both boot-line builders are deleted.
  - The Claude session owns the app's life: the app carries a `SPEC_APP` tag, stop kills every tagged process, and every start first reaps what a dead session left in this repo (`lib/reap.js`).
- I will not touch:
  - Chat pins, the contract shape, pin tests in GATE, LOOK's literal, pictures, `drop`, the plan lock's coverage check (spec 20261105/14, ADR-0043); the marks' own checks and the version self-check (spec 20261108/02).
  - `release.*`, `walkthrough.*`, `setupCommand`'s meaning, the gate and its cache.
- Users will notice: a prototype opens on a monorepo that boots two fixed-port apps with one command; the session never types `cd … && export PORT=… && …`; the app stops when the prototype closes or the run ends, and a server a dead session left in this repo is gone at the next start; the config has a `runtime` block instead of `prototype.bootCommand`.
- You lose: `prototype.bootCommand`, `prototype.url`, `prototype.publicUrl` (moved, by `/spec:migrate`); the printed boot line.
- Architecture or behaviour change: yes — the host's runtime is one declaration and one owner (ADR-0049, amending ADR-0043's "A host needs `prototype.url` and `bootCommand`"), needs your yes
- Client sign-off: where the start command lives and when a prototype restarts its app — JJ chose one `runtime` block (old `prototype.*` keys moved by `/spec:migrate`, the old shape refused after) and a restart only when the app has died; JJ's yes on the architecture change (ADR-0049)

## Goal

On a host whose config says `runtime: {bootCommand, readyCheck}` and nothing under `prototype` but `e2eFile`/`e2eCommand`, `/spec:prototype` opens, boots the app itself, prints the ready line only when the host's own ready check passes, and `closed` leaves no process behind; `/spec:run` boots the same way for pin tests and LOOK and stops it at the end. Config with `prototype.bootCommand` refuses every command naming `/spec:migrate`, which moves it.

## Acceptance Criteria

- **AC-20261108-01-1**: WHEN a host's config holds `runtime: {bootCommand: <stub server on $PORT>, url: "http://127.0.0.1:{port}"}` and no `prototype.bootCommand`, and `prototype.js invoice list page` runs THE SYSTEM SHALL provision the worktree with the `.worktreeinclude` match and the setup marker, start the app itself, print `▶ OPEN` with `app up at http://127.0.0.1:<n>` and no `cd `, `export PORT` or "start the app" text, and write `status.json` with `app.pid` alive and `appPort: <n>`; AND `--mark opened` SHALL exit 0 with no app started by the test.
- **AC-20261108-01-2**: WHEN `runtime.bootCommand` boots two stub servers on fixed ports 4321 and 3100, `url` is `http://127.0.0.1:4321` and `readyCheck` is both urls THE SYSTEM SHALL print `▶ OPEN` only after both answer and `status.json` SHALL hold `appPort: null`; WHEN `readyCheck` is a command exiting 1 until a flag file exists THE SYSTEM SHALL wait for it; WHEN the ready check never passes within `readySeconds: 2` THE SYSTEM SHALL exit 1 naming the log path, leave no process of the app's group alive and write no `marks.opened`; AND WHEN a foreign server already answers at the fixed url THE SYSTEM SHALL exit 2 with `this driver did not start it`.
- **AC-20261108-01-3**: WHEN `runtime.envCommand` writes a marker in the worktree THE SYSTEM SHALL run it before the first boot at OPEN, exactly once across OPEN and three ROUND re-derives, with `PORT` set to `appPort`; AND WHEN it exits 1 THE SYSTEM SHALL exit 1 naming `runtime.envCommand`, start no app and remove the worktree it made.
- **AC-20261108-01-4**: WHEN the app process is killed between rounds THE SYSTEM SHALL at the next ROUND restart it (a new `app.pid`) and print the ready line; WHEN the restart fails THE SYSTEM SHALL print `⚠️ the app did not come up` and no `🎨 ready for pins`; AND WHEN `--mark closed --force` runs at ROUND THE SYSTEM SHALL stop the app (no process of its group alive) before removing the worktree, as `--mark closed` at CONTRACTED SHALL too.
- **AC-20261108-01-5**: WHEN `run.js` gates a `prototype:` spec THE SYSTEM SHALL start the app through `lib/app.js` and run the stub `e2eCommand` with `APP_URL=http://127.0.0.1:<n>`, leave the app alive into LOOK whose body carries `👀 look —` and no `cd ` or `export PORT`, restart it (a new pid) when GATE runs again after `look-failed` and `fixed`, and stop it at `looked` and at a park; AND a spec without `prototype:` SHALL CONTINUE TO start no app.
- **AC-20261108-01-6**: WHEN a config holds `prototype.bootCommand` THE SYSTEM SHALL have `prototype.js --state`, `run.js` and `status.js` exit 2 with `still has prototype.bootCommand — run /spec:migrate`; WHEN `migrate.js` plans on it with `runtime.readyCheck` present THE SYSTEM SHALL list a `config` op, and `--apply` SHALL write `runtime.bootCommand`, `runtime.url`, `runtime.publicUrl` from the `prototype` ones, keep `runtime.readyCheck`, leave `prototype` with only `picture`, `e2eFile`, `e2eCommand`, and a second `--apply` SHALL print `✅ nothing to migrate`.
- **AC-20261108-01-7**: WHEN `spec/` and `docs/v8/` are grepped THE SYSTEM SHALL find zero hits for `withApp`, `allocApp`, `bootCommandOf`, `bootLine`, `export PORT=`, `appUrl` and `prototype.bootCommand` (migrate.js's op text and `migrate.md` excepted); AND `docs/adr/0043-*.md` SHALL carry `Amended by: ADR-0049`.
- **AC-20261108-01-8**: WHEN the stub app `setsid`s a grandchild and `app.stop` runs THE SYSTEM SHALL leave no process carrying its `SPEC_APP` alive; WHEN processes carry the `CLAUDE_PID` of a SIGKILLed stand-in owner THE SYSTEM SHALL have `reap.sweep(root)` kill the one with `SPEC_APP` and the untagged one whose cwd is under `root`, and leave the one whose cwd is outside `root` and one whose owner is alive; AND WHEN a dead owner's app holds the fixed url THE SYSTEM SHALL have `app.start` reap it and boot instead of refusing.

## Assumptions

- A1: Claude Code keeps exporting `CLAUDE_PID` to Bash-tool children (seen 2026-11-08, undocumented) — if false: the owner is the nearest ancestor named `claude`; `tests/reap.test.js` pins the env read, so the loss is a red test, never a silent leak.
- A2: Spec 20261106/01 (queue on trunk) was superseded unbuilt, so this no longer waits on it; its successor touches the queue's write path, not the runtime — if false: rebase onto it, the seams do not overlap in function.
- A3: No host under JJ's projects reads `prototype.url` or `prototype.bootCommand` from anything but this plugin — if false: that host runs `/spec:migrate`, which is the designed path.
